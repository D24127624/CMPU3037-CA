This assignment requires you to identify an application and progress the system through its analysis and design phases.

## Instructions:

* It would be ideal to source a system from your work experience. You will likely need to get approval to release information
in the college environment. The application could be based on work already undertaken for which a non-standard
documentation was done (or none at all). Otherwise, it could be based on a potential project within the workplace. If no
workplace source exists, then identify a project from an application area that you are familiar with.

  - ***Deliverable 1 - Systems Requirements - A single document containing the following: -***

    * The system should be described in at least two pages of an **overview narrative, which should include any available supporting documentation, 
      such as screenshots**, if it is an existing system being enhanced. Mock-ups of screens could also be provided if an existing system is not being
      modelled. The purpose of this overview is to provide an informal description of what you are thinking of in terms of the application.

    * Apart from the overview, the system requirements must be clearly stated using a UML-based approach - a **Use Case Diagram** should be provided 
      showing **at least 6 use cases** of the system. 
  
    * Extended descriptions/narratives must be provided for 3 of those use cases where **at least 2 involve user interaction** with the application.

  - ***Deliverable 2 - Object Model - A single document / image containing the following: -***
  
    * The object model (conceptual class diagram) identified from the system requirements. Should contain classes for all your domain objects, the 
      associations between the classes and any class attributes that are required. There is no need to include operations at this point.

  - ***Deliverable 3 - Analysis / Design Model - A single document containing the following: -***

    * Detailed class diagram showing the structural design. The class diagram should show all classes required, their relationships with other 
      classes, their attributes and their operations.
  
    * At least 3 sets of sequence diagrams which provide the realisation of the initial use cases from deliverable 1. The sequence diagrams should 
      include messages that provide detailed guidance to their implementation.
  
  - ***Deliverable 4 - Presentation: -***

    * You must record a 10-minute (max) presentation of your models. The purpose of this presentation is to show that you fully understand the 
      models. To this end, you should present each diagram and talk through why it is modelled the way it is, e.g. *"these two classes have a 
      unidirectional one-to-many association because..."*
  
    * You will be able to use Brightspace to record and submit your presentation - more information on how to do this will be available closer to the 
      due date. The recording software within Brightspace supports Windows and Mac.

* All the modelling should be done ***using appropriate modelling software*** - it is ***not*** a requirement that you use Visual
Paradigm (but it is highly recommended).

* **Please submit your deliverables as a Microsoft Word documents using the following naming convention:**

  - `SE_CA<deliverablenumber>_lastname_firstname_studentnumber.docx`
    <br/>
    `e.g. SE_CA_Keith_Kelly_A12345678.docx`
